# Structure

OPEN, read first: only the fixed server paths below come from the PRD. The rest
is proposed. Confirm it in the first session and correct this file. Once
confirmed, treat it as fixed.

This file says where files live and what they are called. It says nothing about
what they contain.

## The server boundary

Every module under src/server/ imports the server-only guard on its first line:

  import "server-only";

Reason: without it, a stray import from a client component pulls the database
client and the model keys into the browser bundle, and nothing warns you. The
guard turns that mistake into a build error. rules/ci.md check 7 enforces that
the import is present.

## Fixed server paths

Named in AGENTS.md. These cannot move.

- src/app/api/                    route handlers
- src/server/auth/                sign up, login, sessions, passwords
- src/server/auth/session.ts      the only place the session cookie is read
- src/server/router/              the deterministic never answer checks
- src/server/private/             every private record read
- src/server/checkin/             code generation and eligibility
- src/server/checkin/verifier.ts  the only place a code is consumed
- src/server/retrieval/           the vector query and chunk writes
- prisma/                         schema and migrations
- rules/                          these files
- docs/                           the PRD

## Everything else

- src/middleware.ts            route protection for all three route groups
- src/app/                     member routes
- src/app/staff/               staff routes
- src/app/owner/               owner routes
- src/components/              shared UI components
- src/components/<feature>/    components used by one feature only
- src/hooks/                   client hooks
- src/lib/                     pure helpers, no server or browser dependency
- src/lib/env.ts               the only module that reads environment variables
- src/lib/copy.ts              the only module that holds member facing strings
- src/server/ai/               the model interface
- src/server/ai/prompts/       the prompt files, one per prompt
- src/server/membership/       status and tier computation
- src/server/payments/         gateway calls and webhook handling
- src/server/jobs/             the scheduled job handler
- src/types/                   shared types not generated by the ORM
- public/sw.js                 the service worker
- tests/                       tests, mirroring the src path of the file tested

## Naming

- Files and folders: kebab-case. index-card.ts, not IndexCard.ts.
- React components: PascalCase inside the file, kebab-case filename.
- Test files: <name>.test.ts under tests/, mirroring the source path.

Reason: one convention removes an argument from every review. Which convention
matters less than having one.

## Route separation

Member, staff and owner routes are three route groups with three layouts and
three middleware branches. No shared layout wraps more than one group.

Reason: AGENTS.md requires that staff and owner screens are never reachable from
the member app, and a shared layout is how that quietly breaks.

## The verifier endpoint

When the real keypad verifier replaces the simulated one, its endpoint lives
under src/app/api/checkin/verify/ and is authenticated like the job endpoint in
rules/jobs.md, not like a member route.

Reason: a keypad is a device, not a person. It holds no session and must not be
able to reach anything a member route can reach.

## New folders

Do not create a top level folder under src/ without asking.

Reason: a folder added once becomes a folder everyone adds to.
